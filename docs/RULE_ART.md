Godotゲーム開発における画作りの規約。FcLab（0〜10章）の実機検証で確定した値。
このファイルは正本。新しいチャットの冒頭でこれを貼ること。

最終更新: v1.0（FcLab v1.9 の検証結果）

## 1. 画面

| 項目 | 値 |
|---|---|
| 画面解像度 | **1280x720**（v5.3で640x360から変更） |
| stretch mode | `viewport` |
| stretch aspect | `keep` |
| テクスチャフィルタ | `nearest`（`textures/canvas_textures/default_texture_filter=0`） |
| レンダラー | Compatibility (`gl_compatibility`) |
| 向き | 横持ち（landscape）を既定とする |

**根拠**: 実機で256/384/640/960を比較。256は明確に粗い。960は最もクリアだが、キャラが画面に対して小さくなりすぎてドット絵にする意味が薄れる。640がドットを様式として見せつつ荒さを感じない境界。384も許容範囲で、UI操作性の都合で下げる余地はある。

## 2. スプライトのサイズと色数

| 用途 | サイズ | 色数 |
|---|---|---|
| 全ユニット | **96x96** | **32** |
| マップタイル | 64x64 | 16 |
| 顔グラフィック | 256x256 | 32 |

| UIアイコン | 16x16 | 8 |

**根拠**: 同一被写体（写真）を各サイズで比較した実機判定。

- 32: 何とか分かる
- 48: 何とか分かる
- 64: 識別可能 ← 実用下限
- 96: 特徴まで分かる ← 見せたい対象に使う

色数は 8 が識別不能、16 と 32 は識別可能。**ファミコン基準の3色は写真由来の素材では成立しない**ことが確認された。

### 判定基準（今後サイズを見直すときの定義）

「破綻していない」とは、**動いている最中に一瞬で分かる**こと。じっと見て想像できることではない。

1. 主役が一瞬で識別できる
2. 輪郭が背景から分離している
3. そのキャラ固有の特徴（武器・色・シルエット）が残っている
4. 減色由来のノイズ点が散っていない

## 3. 素材の作り方

### 原則

**背景 = 絵（写真または高解像度描画） / キャラ = ドット** の役割分担。混ぜず、役割で分ける。
実機で合成テストを行い、成立することを確認済み（判定: 良）。

### 調達と加工の分担

| 工程 | 担当 |
|---|---|
| 写真・素材の調達 | 関口 |
| ドット化（縮小・減色） | アプリの自動変換、またはClaude |
| 手直し | 関口（FcLab 0章の編集モード） |
| コード化・動きの付与 | Claude |

大量の素材はアプリで自動変換する。特に重要な素材のみチャットに画像を貼り、Claudeが直接コード化する。

### ドット化の手順（FcLab 0章）

1. `LOAD` で画像を選ぶ（正方形に切り出し、512x512以下に縮小して保持）
2. `SIZE` と `COLOR` を用途に合わせる
3. `EDIT` → `AUTO` で縮小・減色結果をキャンバスに流し込む
4. 必要なら `TRACE` で下絵を敷き、`PICK` で下絵の色を吸いながら手直し
5. `COPY` でGDScript形式をクリップボードへ

減色アルゴリズムはメディアンカット（`Dot.gd` に実装）。

## 4. データ形式

スプライトは文字列配列としてソースコードに直接書く。画像ファイルは使わない。

```
const PAL := ["1b2b1f", "e8dca4", ...]
const ART := [
"....01120....",
...
]
```

- `.` = 透明
- `0`〜`9`、`a`〜`v` = パレット番号（最大32色）
- `PAL` は `#` なしの6桁hex

パレット差し替えで敵味方の色違いを作れる。同じ `ART` に別の `PAL` を渡すこと。

## 5. 採用が確定した表現技法

FcLab 1〜9章で全て「使う」と判定済み。

| 技法 | 内容 |
|---|---|
| スプライト | 4方向、2コマ歩行、左右反転、パレット差し替え |
| 多重スクロール | 3層（遠景・中景・近景）で速度を変える |
| パレットアニメ | 同一タイルで色だけ循環（水面・炎・被弾点滅） |
| ラスタースクロール | 走査線ごとのX方向オフセット（波・地震・水中・ねじれ） |
| インパクト演出 | 画面フラッシュ、揺れ、ヒットストップ、色反転、ダメージ数字ポップ |
| 画面転換 | フェード、ワイプ、カーテン、モザイク、ダイヤ |
| メッセージ | 枠、1文字送り、送りカーソル点滅 |
| ちらつき | 1ライン8スプライト制限の再現（意図的な演出として） |

実装の参照元は FcLab リポジトリの各章スクリプト。

## 6. 動きの方針

ドットは高速で動かさない。**基本位置からの移動速度を抑える**ことで、粗さを問題にしない。

- タイル単位の移動、ターン制と相性が良い
- 歩行は2コマ、上下の揺れは控えめ
- 速度・揺れの具体値は `RULE_FEEL.md` で確定させる（未着手）

## 7. フォント

Godot標準フォントには日本語グリフが無い。以下のいずれか。

- アプリ内表示を英大文字に限る（FcLabの方式）
- 自前のビットマップフォントを用意する（`Gfx.gd` に5x7の英数フォントあり）
- 日本語が必要な場合は、日本語フォントを同梱するか、文字もドットデータとして持つ

**本番で日本語を出す方針を決める必要がある。未確定。**

## 外部素材の運用（v5.1〜）

`art/` に置いたPNGが、コード内のドット絵より優先される。無ければコード側にフォールバックする。
ファイル名は内部キーと一致させる（例 `KNIGHT0.png`）。透過背景が必須。

`artsrc/` には背景を抜いた高解像度の原画を保管する。`.gdignore` を置いてあるのでGodotは読み込まない。
サイズや色数を変えたくなったら、ここから作り直す。**生成AIに同じ絵を作り直させる必要はない。**

### 生成AIからの受け入れ手順

1. 生成時のプロンプトに `chibi proportions, about 3 heads tall` `flat cel shading, thick dark outline, no gradients` `SQUARE image` `plain magenta background` `no shadow on the ground` を必ず入れる
2. 2体目以降は1体目を参照画像として渡し `same art style as the reference` を付ける
3. Claude側で四隅から背景色を自動判定して抜き、輪郭で切り出して正方形に整え、96x96・32色へ減色する
4. `art/` に書き出し、`artsrc/` に原画を保管する
